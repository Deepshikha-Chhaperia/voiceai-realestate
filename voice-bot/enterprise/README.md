# Enterprise configuration-gated build

This module adds no live provider calls during import. Do not deploy by copying example values. Existing Sarvam STT/TTS, Groq models, voice, pace, endpointing and audio purge settings are unchanged. AI call duration is capped at240seconds; this is a business safety cap, not an STT latency adjustment.

## Deployment boundary

Supported ledger deployment: a single host, shared persistent DATA_DIR volume, multiple local processes. Atomic SQLite transactions reserve monthly calls and seconds before admitting AI or human calls, and claim background work before external side effects. This is not a distributed multi-host quota system. Do not enable multiple hosts against copied/local ledgers. Existing PostgreSQL stores CRM, while enterprise.db stores quota/work outcomes.

enterprise.enabled defaults false. Fill existing project UUID and tenant, limits and reset timezone, accounting scope, persistent deployment confirmation, reps and hours, approved callback wording. Configure human recording notice/consent/retention/access, trusted media host and batch Sarvam model explicitly. Missing/invalid policy means not ready, never a made-up usable default. Read GET /enterprise/readiness with existing dashboard Bearer key. Routing readiness is not an end-to-end carrier test. Inbound enterprise calls fail closed if policy or caller persistence is unavailable. Anonymous callers produce an event, not an invented phone lead. Enterprise outbound is opt-in disabled until outbound_enabled and verified_lead_optin policy are set. Admission reserves before dial, requires existing lead consent_at, sets provider time_limit and hangup_url, and binds returned request_uuid. Unknown POST outcomes retain reservations without re-dial. A provider time_limit also caps the full outbound call, so transferred outbound human duration remains within that original limit.

Monthly quota is application-routed call seconds, including bridge extension, not a carrier invoice. Transfers create two billable legs: current policy does not aggregate B-leg invoice seconds. Caps prevent new admission and reserve full maximum before dialing. At100% committed capacity new calls stop. An unexpected process exit leaves reservation held, not silently released; confirm provider end/duration and use authenticated reconciliation. A signed end callback or matching finalized CDR finalizes. AI teardown alone does not. The application hard timeout requests hangup, but only actual provider confirmation proves PSTN billing stopped. Carry this into go-live tests.

## Intent and scoring

First10seconds collect explicit buyer/broker/job/wrong-number intent. Unknown is retained as unknown and is not junk. Lone yes/no, numeric choices and ordinary long speech are never machine/spam evidence. Repeat status comes from scoped existing phone/project record and is independent of intent. Explicit nonbuyer close uses60seconds, maximum hard ceiling still240. Broker/job policy must select close or route. Buyers continue existing bot flow.

Enterprise AI calls queue deterministic scoring after caller-role evidence extraction using existing Groq postcall analysis. Missing budget/timeline stays unknown; no guessed hot lead. Approved database visit state verifies booking. Hot/warm/cold + pending insufficient evidence has visible reasons. Existing legacy lead worker behavior remains unchanged for nonenterprise calls.

## Human mode and routing

Public Vobiz inbound webhook must target this app. Human mode generates notice + Record + simultaneous Dial of configured reps. No recording of unrelated existing phone/landline calls is implied. Ring/hold is capped at50seconds, below1minute. Configured max human bridge duration is separately reserved. Transfer POST is a bounded8second attempt: initiated is not connected. Signed DialConnected establishes connection; busy/no-answer/failure creates callback work. Stream teardown after transfer does not hang up an accepted/uncertain transferred call. Timeout/unknown transfer is not retried.

A supported recording consent deployment currently uses an owner-approved notice-and-continue policy. Explicit press1/opt-in IVR is not implemented and readiness fails for that policy. Provider recordings/transcripts are private to existing shared dashboard-key holders, not per-user role-based access. Sarvam batch jobs are created only by enabled human worker. Model is explicit, no live STT model replacement. Durable work records job ID before upload/start; errors remain needs_operator, with no duplicate automatic paid job. Sarvam diarization speaker numbers are not caller identity: transcript is retained but qualification stays pending until operator reviews caller-specific facts through human-review API. This does not claim automatic role attribution is solved.

Retention removes local transcript content from CRM and enterprise work after expiry. It does NOT delete vendor media or Sarvam retained data; configure provider deletion/retention and include it in operational checklist before recording go-live. Do not claim regulatory compliance from a config flag. Downloads require exact approved provider host, public HTTPS and no redirects, with64MB bound.

## Dormant Meta automation

Leave WHATSAPP_AUTOMATION_ENABLED=false until the real account is ready. Required: access token, phone_number_id, WABA ID, explicit supported API version, app secret, webhook verify token, approved template map with language + ordered BODY fields, verified brochure/floorplan/location URLs, and configured HTTPS webhook subscription/live mode confirmation. No APIversion inferred as 'latest'. No test recipient override, freeform24hour-window guessing, fake map URL or hello_world production fallback.

Read-only startup/4minute validation checks WABA phone membership/verification and exact approved template/language/schema. Supports positional text BODY templates with static headers/buttons. Media/dynamic headers, named variables or dynamic buttons fail readiness rather than being filled incorrectly. Webhook setup confirmation is operator evidence, not automatic proof. A fresh readiness check is required after env change; redeploy/restart loads env but no code changes needed for supported schemas.

Caller action consent is stored separately for brochure/location, never inferred from lead.consent_at. Postcall teardown queues once by tenant/call/action. Automation sends one attempt only. Accepted means Graph returned message ID, not delivered. Signed status webhook changes sent/delivered/read/failed, ignores other WABA/phone and downgrade events. Uncertain outcomes or worker crash never auto-resend. Credential/policy failure retains manual message output and exact not-ready gaps. Legacy WhatsApp outbox is disabled and must be reconciled manually, never automatically drained after the new config activates.

## Alerts, CRM and reports

GET /enterprise/work exposes local70/85/100alerts, callback/missed-call work and provider outcomes. It is an authenticated operator queue, not external notification delivery. Acknowledge only after review; do not claim alert email/WhatsApp sent without a delivery adapter. Legacy dashboard is unchanged and does not yet have a cold column; GET /enterprise/crm is project-scoped and shows cold scores/reasons. Visit completion/no-show/cancellation updates preserve touchpoints. No synthetic caller phone, arbitrary project choice or blanket marketing opt-in in enterprise ingestion.

Fortnightly report is14days from explicit local anchor/timezone, with configured brand, call usage, caller tier/reason and visit status. It is prepared_not_sent, downloadable as authenticated JSON or printable escaped HTML. No audience/delivery channel guessed. Auto email/WhatsApp report distribution is not implemented. Review caller PII before onward sharing. Every report run is idempotent by period; current implementation produces latest complete period, not automatic missed-period backfill.

## Offline verification and go-live

No product tests are part of the patch. Configured transcript_retention_days covers new enterprise work payloads only; existing logs, lead_state records and provider copies have their own lifecycle, explicitly confirmed before activation. Separate regression bundle covers atomic admission/claims, idempotency, config/schema/consent/readiness, timeout uncertainty, signed webhook, scoring and intent. Do not run paid tests from these instructions. Production readiness still requires authorized matched PSTN calls: signed handshake/form field verification; rep connected/busy/noanswer; true AI ceiling/PSTN termination; crashed reservation reconciliation; actual recording-ready callback shape; human speaker review; approved template accepted/delivered/failure, webhook signature and duplicate/out-of-order events; report audience review. Do not write0.5s latency or2min delivery in a contract. Existing matched live latency/cost gates are unmeasured for this build.
